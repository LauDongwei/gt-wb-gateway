> 场景：这台机器（公司/常开）装着 WorkBuddy 登录态，跑着 gt-wb-gateway。
> 想把它的模型能力**稳定**地给家里的私人电脑用。

## 架构：账号只有一个出口

```
┌──────────────┐   ZeroTier 加密隧道   ┌────────────────────────┐         ┌──────────────────────┐
│ 家里电脑      │ ───────────────────▶ │ 这台机器 (常开)         │ ──────▶ │ copilot.tencent.com  │
│ Codex / CC   │   <家里机ZeroTier地址>     │ gt-wb-gateway :8787    │         │ (WorkBuddy 订阅后端)  │
│ Switch       │ ◀─────────────────── │ WorkBuddy 登录态（唯一）│ ◀────── │                      │
└──────────────┘   <服务机ZeroTier地址>     └────────────────────────┘         └──────────────────────┘
      不带 WorkBuddy 客户端                   账号从这里出去              风控看到的是「一个客户端」
```

**这层设计就是稳定性的关键**：家里电脑只是一个 HTTP 客户端，账号本身始终只在这一台机器上登录。
对腾讯后端来说，请求依然来自同一个客户端 —— 只是请求变多了。

## 第一步（公司机侧）：已经做完了，只有两处改动

以管理员身份执行：

```powershell
cd D:\workbuddy\研究院\gt-wb-gateway
.\deploy\setup.ps1 -ZeroTier -SkipTask
```

`-ZeroTier` 会自动读取 ZeroTier 网卡、算出网段，把下面两件事一次配好：

| 改动 | 内容 | 为什么安全 |
|---|---|---|
| `config.json` 的 `host` | `127.0.0.1` → `0.0.0.0` | 只改监听地址 |
| 防火墙入站规则 | 放行 TCP `8787`，**来源锁定 `192.168.191.0/24`** | 物理局域网、公网**一律进不来**；只有 ZeroTier 私网内的设备能连 |

**这两处都不涉及公司网络**：不开公网端口、不改公司路由、不动公司服务器和 IT 策略。

撤销：`.\deploy\uninstall.ps1`（会删掉规则与计划任务）

> `config.json` 里是**明文 API Key**，别外发。它已在 `.gitignore` 里。

## 第二步（家里电脑侧）：3 步接上

### 1. 家里电脑装 ZeroTier 并加入同一网络

1. 装 ZeroTier（官网 msi，一路下一步）
2. 托盘右键 → `Join Network` → 填网络 ID：`<你的24位网络ID>`
3. 去 [ZeroTier Central](https://my.zerotier.com) 找到该网络，勾选新设备前面的 **Auth** 授权（网络是 PRIVATE 类型，必须手动授权）

加入后家里电脑会分到一个 `192.168.191.x` 地址。**验证**：

```powershell
ping <服务机ZeroTier地址>
curl http://<服务机ZeroTier地址>:8787/health
# 期望返回：{"status":"ok","service":"gt-wb-gateway"}
```

看到这段 JSON 就说明通了（不含账号信息是**故意**的，对外只暴露这两个字段）。

### 2. 确认 Clash 不捣乱（一条规则）

**这台公司机已实测**：Clash 的 TUN 抢的是默认路由，而 ZeroTier 的 `192.168.191.0/24` 是更具体的路由前缀，**优先级更高，不会被 TUN 吞掉**，所以公司机侧无需改动。

家里电脑同样加一条直连规则最保险（放在 `rules:` 最前面）：

```yaml
rules:
  - IP-CIDR,192.168.191.0/24,DIRECT,no-resolve
```

### 3. 把模型接进 Codex / CC Switch

两种方式，**家里有 CC Switch 就用方式一**。

## 稳定性清单（这五件事决定「稳不稳」）

| 事项 | 状态 | 说明 |
|---|---|---|
| ZeroTier 常驻 | ✅ 已是 Windows 服务，随开机自启 | 无需配置 |
| ZeroTier 地址固定 | ✅ 控制器分配，不会每次变 | 与免费隧道的本质差别 |
| 服务常驻 + 崩溃自愈 | ⚠️ **待确认** | 需要注册计划任务：`.\deploy\setup.ps1 -ZeroTier`（去掉 `-SkipTask`） |
| 不睡眠 | ✅ 本机已是「永不」 | `powercfg /change standby-timeout-ac 0` |
| 登录态自动续期 | ✅ 网关内置 | 到期前用 refreshToken 换新并**原子回写**登录态文件 |
| 日志不写爆磁盘 | ✅ 已做 | 单份上限 8MB 自动轮转，只留最近两份 |

**唯一不能自动恢复的情况**：WorkBuddy 桌面端被登出、或 refreshToken 也失效。
这时需要在公司机上重新登录一次 WorkBuddy。

## 🚩 红线（务必守住）

1. **家里电脑不要装 WorkBuddy 客户端去登同一个账号。**
   那才是真正的「多设备登录 / 异地登录」——会互相踢下线，也正中腾讯风控的判定条件。
   家里只跑 Codex / CC Switch 这类**纯 HTTP 客户端**，账号始终留在这台机器上。
2. **不要搞账号池 / 多账号轮转。** 配置项 `allow_account_rotation` 默认关闭，保持关闭。
3. **别把频率拉满。** 两台机器同时跑密集 agent 任务 = 请求量翻倍，是「高频调用」风控的直接触发项。
4. **不要把这个服务映射到公网。** 走 ZeroTier，防火墙来源已锁死在 `192.168.191.0/24`，别去放开它。
5. **API Key 别外发。** `config.json`、深链、`state.json` 都含敏感信息。
6. **ZeroTier 网络保持 PRIVATE。** 别改成 Public，也别把无关设备授权进来。

## 排错对照表

| 现象 | 大概率原因 | 怎么查 |
|---|---|---|
| 家里 `ping <服务机ZeroTier地址>` 不通 | 新设备没在 ZeroTier Central 授权 / 不在同一网络 | 家里 `zerotier-cli listnetworks` 看状态是否 `OK` |
| ping 通但 `:8787` 连不上 | 公司机服务没起 / 防火墙规则被删 | 公司机 `netstat -ano \| findstr 8787` 看是否 `0.0.0.0`；`Get-NetFirewallRule -DisplayName "gt-wb-gateway*"` |
| 时通时不通 | ZeroTier 从直连退回中继 | 公司机 `zerotier-cli peers`，看 LEAF 的 link 是 `DIRECT` 还是 `RELAY` |
| 返回 401 | 客户端没带 key，或 key 打错 | `curl -H "Authorization: Bearer <key>" .../v1/models` |
| 返回 200 但模型报错 | 模型名不是后端真实支持的 | 先 `curl .../v1/models` 拉真实清单 |
| 家外面 `/health` 只返回 `status+service` | **正常**，有意为之 | 详细诊断信息只对本机回环开放 |
| 长时间不用后全部 401 | WorkBuddy 登录态过期 | 公司机上看 `/health` 的 `token_expired`，必要时重新登录 WorkBuddy |
| 间歇性超时 | 隧道重连 / 上游审核拦截 | 看公司机 `gtwb.log`，有 rid 和错误分类 |
