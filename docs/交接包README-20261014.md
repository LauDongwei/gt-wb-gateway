# gt-wb-gateway · MacBook 交接包

给**新 MacBook 上的 WorkBuddy** 用的部署包。目的是让它自己把这台 Mac
搭成一台独立上游（用自己的 WorkBuddy 订阅对外提供模型 API）。

---

## 怎么用（给 Michael）

**方式 A：GitHub（推荐，Mac 上网就能拉，且能持续升级）**

把这个包的 `HANDOFF.md` 全文复制，粘贴给 Mac 上的 WorkBuddy，
再告诉它一句：

> 源码在这里 `git clone https://github.com/LauDongwei/gt-wb-gateway.git`，
> 部署指南在仓库里的 `docs/部署指南-macOS-20261014.md`。
> 另外把这份排障手册装成你的用户级 skill：
> `~/.workbuddy/skills/gt-wb-gateway/SKILL.md`

**方式 B：这个 zip（离线也行，适合先跑通再迁到 GitHub）**

1. 整个 zip 传到 Mac（AirDrop / 微信 / 网盘都行，**不要用 rar**，macOS 不能原生解压）
2. 解压后把 `HANDOFF.md` 全文复制粘贴给 Mac 的 WorkBuddy
3. 它会照着里面的步骤 clone 仓库、按指南部署

## 关键提醒

1. **代码走 GitHub，这个包是"知识 + 脚本"**。源码本体不在 zip 里
   （`git clone` 更可靠，也便于以后 `git pull` 升级）。
2. **macOS 与 Windows 的差异已在指南里单列**（第 7 节），最要紧的三条：
   - 健康探测必须 `curl --noproxy "*"`（装了代理会被劫持，导致看门狗拉起僵尸进程）
   - `serve-loop.sh` 必须是 LF 行尾（CRLF 会报 `bad interpreter: /bin/bash^M`）
   - Python 是 `.venv/bin/python`，没有 `Scripts/`（那是 Windows）
3. **红线在 `HANDOFF.md` 里**：严禁把 `*.info` 登录态、`state.json` 跨机拷贝
   （等于把两个账号合成一个，会触发风控封号）。
4. **包内含这台机器的内部信息**（ZeroTier nwid、账号 uid、公司名），
   供 Mac 上的 WorkBuddy 参考。**不要传到任何公开仓库**。
   但注意：**具体 IP / nwid / 模型清单在 Mac 上要以它自己探测为准**，不要照抄。

## 部署成功后 Mac 端要回执的

```
1. macOS 版本 / 芯片架构 / git commit
2. 本机自己生成的 API Key（完整明文）
3. /v1/models 实测清单（常用 3-5 个模型名）
4. /health 的 account.domain 与 account.nickname
```

拿到后把 (2)(3) 配进 Mac 上的 CC Switch / Codex 即可用。
