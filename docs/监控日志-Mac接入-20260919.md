## 三、P0 —— 并行工具调用 + 图片输出 → 上游 400 `11148`（已修复）

### 现象

```
22:38:13 [ecebeb18] ◀ 200 | finish=tool_calls | tools=['view_image', 'view_image']
22:38:14 [a8da845a] ▶ input_items=101 chars=169277 tools 193→193
22:38:16 [a8da845a] ↻ 上游 400，改用紧凑模式重试一次
22:38:18 [a8da845a] ✗ HTTP 400 | {"code":11148,
          "msg":"tool calls and tool results do not match, please start a new conversation and retry"}
```

- **紧凑模式重试无效** —— 因为问题在对话结构，不在长度。
- 这是**整条会话唯一一次失败**，且**直接打断了 Mac 上的 agent 任务**（此后 4 分钟无请求）。

### 根因

`responses_adapter.py::_convert_input_items` 在处理 `function_call_output` 时，
把工具输出里的图片摘出来后**立刻**插一条 `user` 消息承载：

```python
messages.append({"role": "tool", "tool_call_id": ..., "content": text_out})
if images:
    messages.append({"role": "user", "content": [图片...]})   # ← 插在两条 tool 之间
```

单次调用没问题，但**一轮返回两个 `view_image`** 时结构变成：

```
assistant(tool_calls=[A, B])
tool(A)
user(图片)      ← 隔断
tool(B)
user(图片)
```

Chat 协议要求 `assistant.tool_calls` 之后**连续**跟上同等数量的 tool 消息。
B 被 user 消息隔开 → 上游判定配对失败 → `11148`。

### 证据（离线复现，确定性）

`_t/repro_11148.py` 用同一份转换函数构造四种场景，修复前：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 单个 `view_image`（含图） | ✓ 合法 | ✓ 合法 |
| **两个并行 `view_image`（各含图）** | **✗ 破坏** | ✓ 合法 |
| 两个并行 `exec_command`（纯文本） | ✓ 合法 | ✓ 合法 |
| 两个并行，仅一个带图 | **✗ 破坏** | ✓ 合法 |

**与日志完全吻合**：`exec_command`×2 成功、`view_image`×2 触发 400 —— 差别只在有无图片消息插入。

### 修复

把图片消息**延迟到整组 tool 结果之后**统一发出：

- 新增 `pending_tool_results` 缓冲，`function_call_output` / `*_call_output` 先进缓冲；
- 新增 `_flush_tool_results()`：先输出**全部** tool 消息，再输出一条合并的图片 `user` 消息；
- 循环中遇到任何非工具结果项（及各分支收尾处）触发 flush。

修复后 `assistant(tool_calls=[A,B])` → `tool(A)` → `tool(B)` → `user(图片A+图B)`，配对连续合法。

**回归测试**：`tests/test_gateway.py` 新增 4 项断言（131 → **135 项**，全过）。

> **对已经中断的会话的影响**：转换在网关侧逐次重算，客户端不需要新建会话 ——
> **同一个会话直接继续即可，不会再触发 11148**。

## 四、P1 —— `web_search` 被静默丢弃（协议边界，非缺陷）

Codex Desktop 声明了服务端托管工具：

```json
{"type": "web_search", "external_web_access": true}
```

Chat 后端无法承接 hosted tool，网关只能丢弃（`responses_adapter.py` L466）。**丢弃是正确处理**：
若伪造成 function 发出去，模型会调用一个客户端根本无法执行的工具。

**实际影响**：Mac 上的 Codex **失去联网搜索能力**。模型知道工具列表里没有它，不会编造搜索结果，
但如果任务依赖联网查资料，会表现为"查不了"。

**可改进点**：当前每轮都重复打日志（29 分钟内 283 次全库累计），属噪音，见 P3。

## 五、P2 —— namespace 工具 `js` / `js_reset` 被跳过（待抓包确认）

```
⚠ namespace mcp__node_repl: skip tool 'js' (empty or name collision)
⚠ namespace mcp__node_repl: skip tool 'js_reset' (empty or name collision)
```

`_convert_tools_for_chat` 用**全局** `used_names` 去重，同一裸名在多个 namespace 出现时，
**后者被静默跳过**。Mac 侧声明了 193 个工具（含多个 MCP namespace），是否存在误伤需要证据。

**风险**：若 `js` 被跳过而模型又需要它，`mcp__node_repl` MCP 的 JS 执行能力等于被削掉一半；
若只是同一服务器的重复声明，则无害。

**待办**：抓一份 Mac 的真实请求体（`capture_dir` 已开启），确认 `js` 出现在哪些 namespace、是否真的重名。

  「无进展轮」，直接进收尾轮，不再开一次完整的上游往返。任一 query 是新的则照常续搜，
  绝不打断正常的补充检索。
